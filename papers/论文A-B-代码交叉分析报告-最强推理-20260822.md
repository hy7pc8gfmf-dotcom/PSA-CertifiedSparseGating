## 2. 论文与代码不一致（投稿前须修正项）

### 2.1 [P0] `softmax_l1_bound_exp` 紧度常数错配
- **论文自述**：摘要 / §1（`论文A.md:30`）/ §4（`论文A.md:78`）均称
  `‖softmax z − softmax z'‖₁ ≤ 2(e^d − 1)`。
- **代码事实**：`softmax_l1_bound_exp`（`PSA_framework.v:2327-2346`）实际证明
  `list_sum_R (…) ≤ exp (2 * d) − 1`（第 2331 行）。
- **推理**：对任意 `d > 0`，`e^{2d} − 1 = (e^d − 1)(e^d + 1) > 2(e^d − 1)`（因 `e^d + 1 > 2`）。
  故代码证明的是**更松**的上界；论文标注的是**更紧**的常数——**论文高估了该引理的紧度**。
- **不阻塞链条**：末端 `certified_attention_approx` 输出界 `e^{2√ε} − 1 · V_max`（论文 A §1 `:31`，代码链 `linf_le_sqrt_sqsum → softmax_l1_bound_exp(d=√ε) → weighted_avg_lipschitz`）自洽正确。
- **修正动作**：论文三处 `2(e^d − 1)` 改为 `e^{2d} − 1`（或另行补证更紧界——但补证属额外工作，投稿前最低成本是改标注）。

### 2.2 [P0] 论文 B §5.1 基线数值笔误（13.06 → 13.69）
- **论文自述**：`论文B.md:100` 称 "psi-rope C=4 @4096 = **13.06**"，"领先 **21.6%**"。
- **代码/数据事实**：同文种子明细表 `论文B.md:155` 给出
  `psi-rope（几何旋转 C=4，b64 s1337）@4096 = **13.69**`。
- **数值校验**：`(13.69 − 10.74) / 13.69 = 2.95 / 13.69 = 0.2155 ≈ 21.55%`，恰等于论文所写的 21.6%。
  而用 13.06 则 `(13.06−10.74)/13.06 = 17.8% ≠ 21.6%`。
- **结论**：`13.06` 是 `13.69` 的笔误；主表 C=4 = `12.75±0.34`（3 种子均值）保持不变。
- **修正动作**：§5.1 正文 13.06 → 13.69；"领先 21.6%" 表述保留（基于单种子基线）。

### 2.3 [P1] τ 三剪协议切换未显式标注
- **事实**：§8.4 τ 三剪 baseline `E5'' = 12.89` 为 **eval-only 换 θ** 协议，与主表训练值 `12.40±0.74` 是**不同协议**。

## 3. Soundness 风险重新评估（修正上一轮错误推断）

### 3.1 关键反转：OCaml 提取为一元 Peano `nat`，无机器字溢出
- **代码事实**：`psa_guard.ml:6-8`
  ```
  type nat = O | S of nat
  ```
  `add`/`mul`（`:34` 起）均为对一元 `nat` 的递归定义；`pair_den = mul (mul 2 (sub n2 n1)) (Nat.sqrt (mul n1 n2))` 与 `row_le_4_5`（`:320`：`5·num ≤ 4·den`）均在任意精度 Peano 算术上运算。
- **推论**：**不存在 63-bit 机器字溢出**，`row_le_4_5` 比较不会因 wraparound 翻转。
- **影响**：上一轮摘要"OCaml 63-bit 溢出 → 假阳性 soundness 缺陷"的推断 **不成立**，本节正式驳回（Reject）。

### 3.2 真实 residual：提取信任，而非 FFI 证明
- OCaml 检查器是 Coq `frame_check_instance` 的**提取产物**（非独立手镜）；其 soundness 由 `frame_check_instance_sound`（M0）经 Coq **提取机制信任**传递。
- 24/24 FFI 校验仅为**回归测试**，不构成等价性机器证明。
- **修正动作**：论文"实现/审计"节应明确写"soundness 继承自 Coq 提取信任 + FFI 回归校验"，而非暗示"经验等价即充分"。

### 3.3 论文当前溢出节须重写
- 论文仅承认"溢出误拒"（假阴性）；但当前一元 `nat` 提取**根本无溢出**，故该"假阴性"担忧对当前产物亦不成立。
- **修正动作**：删除两类溢出说法，改为标准"提取信任 + FFI 回归"表述（见 3.2）。

### 3.4 唯一真实部署风险（条件性）
- 若部署环境为提速而改用 `Extract Inductive nat => int`（62-bit 定宽），则大 `N` 下 `pair_den` 可能溢出 → `row_le_4_5` 翻转 → **假阳性（放行本应拒绝的阶梯）**。
- **修正动作**：在"实现注记"中显式警告——**禁止将 `nat` 提取为定宽 `int`**；如需提速改用 `Z` / `Big_int`。
